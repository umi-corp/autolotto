# 문의 게시판 연동 설계 (2026-11-12)

## 목적

앱 설정에서 문의 게시판(`support.umicorp.kr/autolotto`)을 바로 연다. 운영자가 답변하면 앱 안에서 표시한다. 게시판 서버는 umi-corp/company 스펙 #5로 이미 구현했다. 이 문서는 앱 쪽 연동만 다룬다. AutoLotto720도 같은 설계를 쓰고, 서비스 이름만 `autolotto720`이다.

## 범위

- 설정 화면의 "문의" 항목
- 게시판 주소 생성과 Custom Tabs 열기
- 기기 키 생성과 보관
- 상태 API 확인과 "문의" 항목의 새 답변 표시 점

## 비범위

| 항목 | 이유 |
|---|---|
| 앱 안 웹뷰 | 게시판의 세션 쿠키와 Turnstile은 브라우저에서 동작하고, Custom Tabs로 충분하다 |
| 푸시 알림, 앱 아이콘 배지 | 스펙 #5의 비범위다 |
| 답변 알림 메일 | company#16은 2026-11-12에 보류했다 |
| 기기를 바꿀 때 기기 키 이전 | AutoLotto에는 데이터 이전 기능이 없다. 이전 기능이 생기면 그때 키를 이전 대상에 넣는다 |
| 서비스 열기(`ENABLED_SERVICES`)와 배포 | company #17 배포 작업에서 맡는다 |

## 결정

### 진입 위치

설정 화면 "앱 정보" 섹션의 마지막 줄에 "문의"를 둔다. 새 섹션은 만들지 않는다. 줄을 누르면 게시판이 열린다. 읽지 않은 답변이 있으면 줄 오른쪽에 점을 표시한다.

### 게시판 주소

```
https://support.umicorp.kr/autolotto?lang={ko|ja|en}&app_version={versionName}&device={기기}#k={기기 키}
```

- `lang`: 앱 언어 설정 값이다. "시스템"이면 시스템 언어를 쓰고, ko·ja·en이 아니면 넣지 않는다. 그러면 게시판이 `Accept-Language`로 언어를 정한다.
- `app_version`: `BuildConfig.VERSION_NAME`
- `device`: `{제조사} {모델} / Android {버전}`, 100자 이내. 게시판은 이 값을 작성 폼의 숨은 필드로 받아 저장한다.
- `#k=`: 기기 키다. fragment는 서버 접속 기록에 남지 않는다. 게시판 스크립트가 이 키를 세션 쿠키로 바꾼 뒤 주소에서 지운다.

### 열기

androidx.browser의 Custom Tabs로 연다. 의존성이 하나 추가된다. Custom Tabs를 지원하는 브라우저가 없으면 `ACTION_VIEW`로 연다.

### 기기 키

- 처음 "문의"를 누를 때 `SecureRandom`으로 32바이트를 만들고, base64url(패딩 없음, 43자)로 바꾼다.
- 기존 `SecureStore`(EncryptedSharedPreferences)에 저장한다.
- 앱을 다시 설치하거나 데이터를 지우면 키가 사라진다. 그래도 게시판은 새 키로 동작하지만, 이전 문의는 "내 문의"에 나오지 않는다.
- 키는 로그에 남기지 않는다.

### 새 답변 확인

`GET https://support.umicorp.kr/api/autolotto/status`에 `X-Support-Key` 헤더를 붙여 `{unread, waiting}`을 받는다. 문의하지 않은 사용자의 통신을 늘리지 않도록 아래 규칙을 따른다(스펙 #5 User Story 42, 43).

| 상태 | 동작 |
|---|---|
| 키가 없음 | 확인하지 않는다 |
| "확인 필요"가 꺼짐 | 확인하지 않는다 |
| "확인 필요"가 켜짐 | 앱을 시작하거나 게시판에서 돌아올 때 확인한다 |
| `unread` 참 | "문의" 줄에 점을 표시한다 |
| `unread`, `waiting` 모두 거짓 | 점을 지우고 "확인 필요"를 끈다 |
| 네트워크 실패, 404(서비스가 닫힘) | 아무것도 바꾸지 않는다 |

- "확인 필요"는 사용자가 "문의"를 누를 때 켠다.
- 게시판에서 문의 상세를 열면 서버의 열람 시각이 갱신되므로, 돌아온 뒤 확인하면 `unread`가 거짓이 된다.

### 문구

새 앱 문구는 "문의" 항목 이름과 점의 접근성 설명, 두 가지다. ko·ja·en은 `codex-lang-generate`로 생성한다.

## 외부 입출력

| 구분 | 대상 |
|---|---|
| 읽기 | 없음 |
| 쓰기(사용자 동작 뒤) | "문의"를 누르면 브라우저로 게시판 주소를 연다. 앱 버전·기기는 쿼리, 키는 fragment로 간다 |
| 자동 호출 | "확인 필요"가 켜진 동안 상태 API를 호출한다. 키는 헤더로만 보낸다 |
| 금지 | 키를 로그·쿼리 문자열·분석 이벤트에 넣는 것 |

## 검증

1. 단위 테스트(JVM)
   - 주소 생성: 언어 판정, 값 인코딩, `device` 100자 제한, fragment의 키
   - 키 형식: 43자 base64url
   - 확인 규칙: 위 표의 상태 전환
   - 상태 API 클라이언트: MockWebServer로 헤더, JSON 해석, 404·실패 처리
2. 기기 확인(Legion Y700, 서비스가 열린 뒤)
   1. "문의"를 누르면 게시판이 앱 언어로 열린다
   2. 문의를 하나 쓰면 작성 폼에 앱 버전·기기가 채워져 있다
   3. 관리 화면에서 답변하면 앱 재시작 뒤 점이 보인다
   4. 문의를 열고 돌아오면 점이 사라진다

## 미결 사항

- 진입 위치: "앱 정보" 섹션의 마지막 줄로 둘지
- 배포 시점과 버전 번호: 사용자가 정한다
- AutoLotto에는 개인정보 처리방침 페이지가 없다. 게시판의 수집 항목은 umicorp.kr 처리방침(company #17)이 다룬다
