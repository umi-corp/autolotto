# 반자동 번호 설계 (2026-11-22)

## 목적

문의 #11 "게임마다 특정 번호를 고정하고 나머지는 자동으로"를 반영한다. 한 게임에서 번호를 1~5개만 고르면, 나머지 번호는 구매할 때마다 앱이 랜덤으로 채운다. AutoLotto 1.1.13으로 배포한다.

## 범위

- 번호 탭: 수동 모드에서 1~5개만 골라도 확정
- 게임 요약: 반자동 슬롯 표시
- 구매 직전 빈 번호 채우기(예약 구매, "지금 바로 구매" 공통)
- 문구 3개(ko·ja·en)
- `docs/INTERACTION-number-tab.md`의 상태 모델과 시나리오 18 갱신

## 비범위

| 항목 | 이유 |
|---|---|
| AutoLotto720 | 720은 "조 + 6자리" 구조라 일부 고정의 의미가 다르고, 요청도 없다 |
| 동행복권 서버 반자동 genType | 코드와 git 이력에 `"0"`·`"1"`만 있다. 서버 값은 실제 구매로만 확인할 수 있다 |
| 추가 구매(`confirmExtra`) | 저장 설정을 쓰지 않는 자동 전용 경로다 |
| 구매 결과의 고정 번호 표시 | 동행복권 응답에 고정 여부가 없다. 표시하려면 구매 시점 구성을 따로 저장해야 한다 |
| 구매 시 슬롯 순서 보존, 예약 구매 Worker의 중복 파싱 | 기존 동작이다(수동 먼저, 자동 나중). 반자동은 수동 목록에 섞여 같은 규칙을 따른다 |

## 결정

### 슬롯 상태

| 저장값 | 의미 |
|---|---|
| `null` | 미설정 |
| `[]` | 자동 |
| 번호 1~5개 | 반자동 (새로 추가) |
| 번호 6개 | 수동 |

`MANUAL_NUMBERS`의 기존 JSON 형식을 그대로 쓴다. 저장(`saveManualGames`), 복원(`parseManualGames`), 분리(`splitSlots`), Worker 파싱 모두 번호 개수를 검사하지 않아 1~5개 목록이 그대로 통과한다(실측). 새 키와 마이그레이션은 없다.

### 빈 번호 채우기

`PurchaseService.purchase`에서 `buildParam` 직전에 수동 목록의 각 게임을 채운다. 예약 구매(`AutoPurchaseWorker`)와 "지금 바로 구매"(`AppContainer.instantPurchase`)가 모두 이 함수를 지나므로, 고칠 곳은 한 곳이다.

- 순수 함수 `fillSemiAuto(fixed: List<Int>, random: Random): List<Int>`를 companion에 둔다. 1..45에서 `fixed`를 뺀 번호를 섞어 `6 - fixed.size`개를 고르고, `fixed`와 합친다. 6개면 그대로 돌려준다.
- 전제: `fixed`는 1~6개, 중복 없음, 1..45다. 번호 탭이 이를 보장하며, 함수는 따로 검사하지 않는다.
- `fillSemiAuto`의 `random`은 기본값 `Random.Default`를 두고, 테스트만 시드를 넘긴다. `purchase` 시그니처는 바꾸지 않는다. 보안 난수는 쓰지 않는다. 동행복권 자동 번호와 같은 성격이라 예측 가능성이 문제가 되지 않는다.
- 채운 게임은 기존 수동(`genType "1"`)으로 보낸다. `PurchaseResult.manualCount`는 반자동을 포함한다.
- 저장값은 바꾸지 않는다. 매 구매마다 새로 뽑는다.

### 번호 탭

- 확정 조건: `isAuto || selected.size in 1..6`. 6개면 지금처럼 수동, 1~5개면 반자동으로 확정한다. `confirmSlot`의 조기 반환(`NumberScreen.kt:185`)과 버튼 `enabled`(`:306`)를 함께 바꾼다. 0개면 지금처럼 비활성이고 문구도 기존 그대로다.
- 확정 버튼 문구: 1~5개면 `🎲 나머지 N개 자동 ✓`, 6개면 기존 `게임 A 확정 ✓`. 버튼이 화면 폭의 2/3라 슬롯 글자까지 넣으면 넘친다.
- 슬롯 재진입: 기존 `syncEditorToSlot`이 그대로 동작한다. 반자동 슬롯은 수동 모드에 고정 번호가 선택된 상태로 열린다.
- "전부 자동", 초기화, X는 바꾸지 않는다. "전부 자동"은 반자동 슬롯도 자동으로 덮는다.

### 게임 요약

1.1.13은 텍스트 `7, 33, ?, ?, ?, ?`로 냈다. 기기 확인에서 자동만 주사위로 그려져 이질감이 있다는 지적을 받아, 1.1.14에서 요약 줄과 선택 영역을 6칸 칩으로 바꾼다(2026-11-22).

| 칸 | 그림 |
|---|---|
| 고른 번호 | `LottoBall` |
| 구매 때 채울 자리 | 볼과 같은 크기의 청록 원 안에 `Icons.Rounded.Casino`. 두 화면 모두 `SixSlots` 하나로 그린다 |

- 자동은 주사위 6개, 반자동은 볼 N개와 주사위 6−N개, 수동은 볼 6개다. 기존 `🎲 자동 (매주 랜덤)` 문구(`gameSummaryAuto`)는 지운다.
- 시안 4가지(사각 타일, 원형, `×N` 압축, 회색 타일)를 기기 화면으로 비교했고, 볼과 실루엣이 같은 원형을 골랐다.
- 선택 영역은 개수 문구와 볼을 두 줄로 나눈다. 한 줄이면 360dp 폭에서 6칸이 넘친다(6볼 수동 선택에서도 원래 넘쳤다).
- 화면 읽기 프로그램은 자동 "자동 번호", 반자동 "7, 33, 나머지 4개 자동", 수동은 번호 목록을 읽는다.

## 검증

1. JVM 단위 테스트
   - `fillSemiAuto`: 결과가 6개이고, 중복이 없고, 모두 1..45이고, 고정 번호를 포함한다. 6개 입력은 그대로 돌려준다. 1~5개 전부 확인한다
   - `purchase`: 고정 번호 2개 게임을 넣으면 `execBuy` `param`의 `arrGameChoiceNum`이 6개이고 고정 번호를 포함한다(MockWebServer)
   - `parseManualGames` / `splitSlots`: 부분 슬롯이 반자동으로 복원되고 수동 목록에 들어간다
2. `./gradlew testDebugUnitTest` 전체 통과
3. 에뮬레이터: 2개 고르고 확정 → 요약 `?` 표시 → 저장 → 앱 재시작 → 슬롯 재진입 동기화 → 6개 수동과 자동 확정에 회귀 없음
4. 릴리스: `release.md` 1~7단계

## 배포 경로

기능 커밋은 `feather` 브랜치에서 PR로 main에 합친다. 서명 파일(`key.properties`, `autolotto-key.jks`)과 `.env`는 main 체크아웃(`~/Workspace/UmiCorp/autolotto`)에만 있어서, 버전 범프·빌드·릴리스는 그 체크아웃에서 `release.md`대로 진행한다. 파일은 옮기지 않는다.
